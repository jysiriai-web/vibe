# 자동화 스케줄 설계

## Q. 모듈별로 스케줄화가 맞나? → ❌ 아니, **타이밍별 2개**가 맞다
모듈은 5개지만 도는 시점이 달라서 모듈마다 스케줄 걸 필요 없다. 묶음은 **시점 기준**:

| 스케줄 | 무엇 | 언제 | 모듈 |
|---|---|---|---|
| **① 밤 생성 루틴** | 검증 → 훅 → 초안 → 큐 | 밤 12시 (부족하면 아침까지 이어서) | 1+2 묶음 |
| **② 오전 발송** | 승인분 발송 | 오전 9~12시 | 3 |
| ③ 추적 | 회신 동기화 | 주기적 (나중) | 4 |

- ①은 **무인 OK** (생성은 되돌릴 수 있음). 새 브랜드 들어온 만큼만 처리.
- ②는 **사람 승인 게이트** 때문에 완전 무인 아님 → 아침에 검토 후 실행(신뢰 쌓이면 스케줄화).
- 3·4·5는 아직 비었고 타이밍이 ①②에 흡수돼서 따로 스케줄 무의미.

## ①밤 루틴 = "프롬프트 한 개" (cron이 Claude를 깨워 실행)
검증·훅은 Claude 워크플로우라 순수 파이썬 cron으론 못 돈다. 그래서 ①은 **스케줄된 Claude 에이전트**가 아래 지시를 실행하는 형태:

> **[밤 루틴 프롬프트]**
> 6월 탭에서 `발송적합도`가 빈 새 행을 찾아 `verify-brands` 워크플로우로 검증하고 6월 시트에 기입(적합/보류·메일주의). 새로 `적합`된 행에 `gen-hooks`(조심스러운 톤)로 훅 생성 → `apply_hooks.py --apply`로 프리뷰·_발송큐 갱신. **토큰 부족하면 중단(부분결과 보존), 다음 실행에 이어서.** 발송은 절대 하지 않음(사람 검토 후 별도). 끝나면 처리 수치 요약.

## 실행 방식 — 지금 가능 vs 나중
| 방식 | PC | 전제 | 지금? |
|---|---|---|---|
| **세션 실행**(나한테 "밤 루틴 돌려"라고) | 켜둠 | 없음(이미 됨) | ✅ 바로 |
| **로컬 /loop** | 켜둠 | Claude 세션 유지 | ✅ 가능 |
| **클라우드 /schedule** | 꺼도 됨 | repo를 git 원격에 push + `secrets/`(서비스계정키)를 클라우드에 등록 | ⚠️ 전제 필요 |

→ **추천: 일단 세션/로컬로 ①을 한두 번 돌려 검증** → 안정되면 전제(원격+키) 갖춰 **클라우드 /schedule로 승격**(PC 꺼도 매일 밤 자동).

## 전제 갖추는 법 (클라우드용, 나중)
1. **repo 원격**: GitHub private repo 만들어 push (`secrets/`·`.venv/`는 .gitignore라 안 올라감 — 의도된 것).
2. **키 등록**: 클라우드 루틴 환경에 서비스계정 JSON을 시크릿으로 등록(또는 OAuth 토큰). 이게 있어야 클라우드가 시트 접근.
3. `/schedule` 로 위 [밤 루틴 프롬프트]를 매일 0시 cron 등록.

*요약: 모듈별 X → 타이밍별 2개(밤 생성 / 오전 발송). 밤 루틴은 Claude 프롬프트 1개. 지금은 세션으로 검증, 나중에 클라우드 승격(원격+키 필요).*
