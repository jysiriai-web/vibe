# 5_reply — 회신 분류·답장 (⬜ 설계)

## 1. 목적

발송 후 Gmail에 들어온 회신을 폴링해 LLM으로 분류(관심/거절/자동응답/반송/수신거부)하고, 6월 탭의 발송단계·영업단계를 갱신한다. 수신거부는 `_수신거부` 탭에 즉시 영구 등록해 이후 모든 발송에서 차단한다. 관심 건에 한해 2_compose 톤 기반의 답장 초안을 생성하고 **사람 검토 파일로 저장**한다. 자동 답장 발송은 없다.

---

## 2. 데이터 계약

### 입력

| 소스 | 탭/열 | 조건 |
|------|-------|------|
| 구글시트 6월 탭 | `발송단계` 열 | 값 = `발송` (이미 회신 처리된 행은 재처리 안 함) |
| 구글시트 6월 탭 | `이메일`, `브랜드명`, `발송일자`, `메일주의` 열 | 폴링 대상 식별 |
| 구글시트 `_발송큐` 탭 | `Gmail-Message-ID` 열 | 발송 시 기록된 메시지ID → 스레드 매핑 |
| Gmail API (읽기 전용) | 받은편지함 스레드 | 발송된 스레드의 답장 메시지 |
| 구글시트 `_수신거부` 탭 | `이메일` 열 | 교차 검증(이미 제외된 주소 재처리 방지) |

### 출력 (6월 탭 갱신)

| 열 | 갱신값 | 트리거 |
|----|--------|--------|
| `회신` | `Y` | 회신 감지 시 |
| `회신일자` | `YYYY-MM-DD` | 회신 감지 시 |
| `발송단계` | `회신` → `리드` | 분류=관심 |
| `발송단계` | `회신` → `거절` | 분류=거절 |
| `발송단계` | `회신` → `제외` | 분류=수신거부 |
| `발송단계` | `회신` (유지) | 분류=자동응답/반송 (상태 유지, 메모만) |
| `영업단계` | (별도 열, 미정) | 분류=관심 시 `리드` 기입 가능 |
| `회신메모` | 분류 레이블 + 추출 시그널 요약 | 모든 회신 |

### 출력 (`_수신거부` 탭 추가)

| 열 | 값 |
|----|----|
| `이메일` | 수신거부 주소 (소문자) |
| `사유` | `수신거부_회신` |
| `원래월` | `6월` |
| `일시` | `YYYY-MM-DD HH:MM` KST |

> 기존 `suppress.add()` (_shared 인근 3_send/suppress.py) 를 그대로 재사용해 중복 등록 방지.

### 출력 (로컬 파일)

| 경로 | 내용 |
|------|------|
| `5_reply/archive/drafts/YYYYMMDD_{브랜드}.html` | 답장 초안 (관심 건만) |
| `5_reply/archive/drafts/YYYYMMDD_{브랜드}.meta.json` | 원본 회신 요약, 추출 시그널, 분류 근거 |
| `5_reply/archive/run_YYYYMMDD.log` | 실행 로그 |

## 3. 메커니즘

### 3-1. 폴링: Gmail 스레드 회신 감지

1. 6월 탭에서 `발송단계=발송` 행 전체를 읽는다.
2. 각 행의 이메일 주소를 기준으로 `_발송큐` 탭의 `Gmail-Message-ID`를 조회해 원본 스레드 ID를 얻는다.
   - 스레드 ID 없는 행: `회신메모`에 `[스레드ID 없음 — 수동확인]` 기입 후 스킵.
3. Gmail API(`gmail.users.threads.get`)로 해당 스레드를 가져와 발송 이후의 메시지를 선별한다(발송 메시지ID보다 `internalDate`가 큰 메시지만).
4. 회신 메시지가 없으면 해당 행은 이 실행에서 건너뛴다(상태 변경 없음 — 멱등).

### 3-2. 분류: LLM 호출

- 도구: Anthropic Messages API (`claude-haiku-*` 권장 — 분류 단순·저비용).
- 입력: 회신 본문 텍스트(HTML 스트립), 메일주의 플래그, 제목.
- 프롬프트 출력 스키마(JSON):
  ```
  {
    "category": "관심" | "거절" | "자동응답" | "반송" | "수신거부",
    "confidence": 0.0~1.0,
    "meeting_signal": true | false,
    "questions": ["..."],       // 회신에서 추출한 질문 목록
    "tone_note": "..."           // 답장 생성 참고 메모 (1줄)
  }
  ```
- 분류 기준 예시:
  - `자동응답`: 부재중, Out of Office, 자동발신, no-reply 헤더
  - `반송`: Delivery Status Notification, MAILER-DAEMON, 550/552 등
  - `수신거부`: "수신거부", "unsubscribe", "메일 그만", "연락하지 마" 등 명시 키워드
  - `거절`: "필요 없습니다", "관심 없습니다", "내부 방침상" 등
  - `관심`: 위에 해당 없고 질문·미팅 제안·일정 언급 등
- confidence < 0.7이면 분류에 `[저신뢰]` 접두를 붙여 `회신메모`에 기록하고 관심 건도 초안은 생성하되 메타파일에 수동확인 플래그를 세운다.

### 3-3. 상태 기록: 시트 쓰기

- 백업 → dry-run 출력 → `--apply` 시 실제 쓰기 순서를 반드시 따른다.
- `backup.py`로 6월 탭 전체를 CSV 스냅샷(`5_reply/archive/backup_YYYYMMDD_HHMMSS.csv`)으로 저장 후 진행.
- 쓰기는 행 단위 batch update(`ws.batch_update`)로 1회 요청.

### 3-4. 답장 초안 생성 (관심 건 전용)

- 분류=관심인 건만 실행.
- 입력: 2_compose 원본 발송 HTML(`_발송큐` 또는 `2_compose/archive/previews/` 에서 로드), 회신 본문, 추출된 질문·미팅 시그널.
- LLM 프롬프트: 2_compose 템플릿의 톤(격식 없는 제안·직관적 진단)을 유지하면서 회신에서 뽑은 질문에 직접 답하고, 미팅 시그널 있으면 일정 제안 문구를 포함.
- 출력: HTML 초안 파일 + `.meta.json` (분류 근거·추출 시그널 포함).
- 파일 저장만. 발송하지 않는다.
- 초안 준비 완료 시 터미널에 경로 출력: `[초안 준비] {브랜드} → 5_reply/archive/drafts/{파일명}`.

## 4. 상태 전이

```
발송단계 전이 (이 모듈이 수행)

발송
  ├─ 회신 감지 + 분류=관심     → 회신 (회신=Y, 회신일자 기록) → 리드
  ├─ 회신 감지 + 분류=거절     → 회신 → 거절
  ├─ 회신 감지 + 분류=자동응답 → 발송 유지 (회신=Y, 회신메모만)
  ├─ 회신 감지 + 분류=반송     → 발송 유지 (회신메모에 [반송] 기록 → 수동검토)
  ├─ 회신 감지 + 분류=수신거부 → 제외 (_수신거부 탭 추가, 영구)
  └─ 회신 없음                 → 변경 없음
```

이 모듈은 `리드` 이후 단계(미팅·계약·성사)를 건드리지 않는다. 이후 단계는 8_followup 모듈 담당.

## 5. 안전·주의

### 되돌리기 불가 단계 — 사람 게이트

| 단계 | 방식 |
|------|------|
| 시트 상태 갱신 | 백업 → dry-run 콘솔 출력 → `--apply` 플래그 없으면 실제 쓰기 없음 |
| `_수신거부` 탭 추가 | `--apply` 없으면 추가 안 함. dry-run에서 "[DRY] 수신거부 등록: {이메일}" 출력 |
| 답장 초안 생성 | 자동발송 없음. 파일 저장 후 경로만 출력. 발송은 사람이 3_send 또는 Gmail 직접 실행 |

### 이중처리 방지 (멱등)

- 입력 조건: `발송단계=발송` 행만 처리. 이미 `리드·거절·제외`로 갱신된 행은 재처리 대상에서 제외된다.
- 같은 스레드에서 메시지가 여러 개 도달한 경우: `internalDate` 기준 최신 1건만 분류 대상으로 삼고, 나머지는 `회신메모`에 건수만 기록.
- 같은 이메일 주소가 `_수신거부`에 이미 존재하면 `suppress.add()` 내부 중복 체크로 재삽입 없음.
- 실행을 여러 번 돌려도 이미 처리된 행은 다시 건드리지 않는다.

### 자동발송 금지

- Gmail API 스코프를 `gmail.readonly` + `gmail.compose` 로 제한. `gmail.send` 스코프는 부여하지 않는다.
- 초안 생성 후 발송 함수 호출 코드를 모듈 내에 두지 않는다.

### 메일주의 플래그 전파

- 6월 탭의 `메일주의` 열이 비어 있지 않으면 분류·초안 생성 시 LLM 프롬프트에 해당 경고 문구를 주입한다.
- 터미널 출력에 `[메일주의] {브랜드}: {경고내용}` 을 표시.
- dry-run 리포트에서도 메일주의 건은 별도 구분해 출력.

### 야간 실행 제한

- `compliance.within_send_window()` 를 재사용해 야간(21:00~08:00 KST)에는 시트 갱신과 초안 생성도 실행하지 않는다 (분류는 해도 무방하나, 상태 반영은 업무시간 안에 하는 것을 원칙으로 함).
- 실제로는 옵션(`--ignore-window`)으로 예외를 열 수 있되 기본값은 차단.

## 6. 구현 메모

### 예상 파일 구조

```
5_reply/
├── run.py             진입점 — CLI 파싱, 흐름 조율
├── poller.py          Gmail 스레드 회신 감지 (threads.get, 메시지 필터)
├── classifier.py      LLM 분류 (Anthropic SDK, JSON 출력 파싱)
├── drafter.py         답장 초안 생성 (LLM, 2_compose 톤 템플릿 참조)
├── sheet_writer.py    6월 탭·_수신거부 탭 갱신 (batch_update, backup 선행)
├── archive/
│   ├── drafts/        초안 HTML + .meta.json
│   └── backups/       실행 전 6월 탭 CSV 스냅샷
└── README.md
```

### 의존

| 항목 | 출처 |
|------|------|
| `_shared.sheets`, `_shared.backup`, `_shared.config` | `../_shared/` |
| `suppress.add`, `suppress.load` | `../3_send/suppress.py` (직접 import 또는 `_shared` 로 이전 검토) |
| `compliance.within_send_window` | `../3_send/compliance.py` |
| Gmail API | OAuth refresh-token(`secrets/gmail_token.json`), 스코프: `gmail.readonly` + `gmail.compose` |
| Anthropic Messages API | `ANTHROPIC_API_KEY` (.env), `anthropic` 패키지 |

> suppress.py, compliance.py 가 3_send 아래에 있어 cross-import가 발생한다. 두 파일을 `_shared/` 로 올리면 모든 모듈이 깔끔하게 쓸 수 있다 (4_reply-tracker README에도 같은 고민이 있음). 이 모듈 착수 전에 결정 필요.
