# ☀️ 아침 요약 — 야간작업 결과 (1·2단계 통합 · 검수 완료)

> 밤새 만든 것들을 제가 **적대적으로 다시 검수**한 뒤 통합해 쓴 요약이에요.
> 좋은 점만 말하지 않고 **안 된 것·불확실한 것·과장된 것**을 일부러 드러냈고,
> 프로토타입이 부르는 함수와 폴더제안이 건드리는 경로를 **라이브 `src/`·`scripts/` 파일을 직접 열어 대조**했습니다.

---

## (a) 한 줄 결론

밤새 **큰 그림(설계)·클라우드 이전 각론·무인 스캔 워커 프로토타입·LUN8 클릭 대시보드 시안·폴더 재구성 제안**까지 요청하신 **5종이 전부 나왔고 서로 아귀가 맞아요.** 다만 **돈 집행은 아직 문서·목업뿐(코드 0줄)**, 스캔 워커는 **실제 PC에서 한 번도 돌려본 적이 없습니다.** 오늘 필요한 건 새 기능이 아니라, 만든 걸 **대표님 PC에서 딱 한 번 진짜로 돌려보는 것**이에요.

## (c) 추천 방향 한눈에 (관제탑 + 무인워커 · 스캔만 로컬)

```
   사람 →  [클라우드 화면 1개]  (북마크 하나, 검은 터미널·bat·localhost 없음)
              │  "스캔해줘 / 집행해줘" = 구글시트에 '요청 깃발' 하나 꽂기
              ▼
        [구글시트 = 유일한 진실 + 우체통]   ← 새 인프라 0, 바깥으로 나가는 통신만
              ▲
              │  (대표님 PC가 몇 초마다 시트를 '들여다보기'만 함 — 인바운드 포트 0)
   [대표님 PC = 화면 없는 일꾼]  ← 집 IP·진짜 크롬·SMM키가 필요한 '몸 쓰는 일'만 대행
```

**핵심:** 사람이 여는 창은 **클라우드 하나**. 틱톡 스캔·돈 집행처럼 "집 컴퓨터가 꼭 필요한 일"만 PC의 조용한 일꾼이 대신하고, 결과는 시트로 돌아와 클라우드에 보여요. **돈 키(SMM)는 클라우드에 절대 안 올려서**, 지금의 "물리적으로 지출 불가" 안전장치를 한 줄도 안 바꾸고 유지합니다.

## (d) 대표님이 아침에 결정할 것 (5개)

1. **돈 집행 방식 A vs B** — 문서는 **A(=PC 일꾼이 집행, 키는 PC에만)** 를 강하게 추천. B(Vercel에 키 올려 PC 꺼져도 집행)는 "비번만 알면 어디서든 지출"으로 안전이 약해져요. **A로 가면 될지 확인만** 하면 됩니다. (돈은 3단계라 급하지 않음)
2. **그 PC가 데스크톱인가, 노트북인가?** — 설계 전체가 **"PC가 늘 켜져 있음"** 전제예요. 노트북이 밤에 절전으로 자면 **저녁 무인 스캔이 조용히 안 돕니다.** 상시 켜두거나 절전 해제 설정 필요. (가장 현실적인 약점)
3. **LUN8 인스타 = 당분간 수기입 확정?** — 틱톡만 자동 스캔, **인스타는 자동 스캐너가 없어 수기입**이에요. 목업도 이 전제로 정직하게 그렸어요(검수·비고·링크·조회수는 인스타도 화면에서 바로 입력). 인스타 자동수집은 별건 대공사 — 이대로 진행할지.
4. **폴더 새 이름 택1** — 추천 **`campaign-hub`**(브리프 예시와 일치·범위 정확). 대안 `campaign-ops`(운영 강조)·`campaign-desk`(한 화면 컨셉). 하나만 골라주세요.
5. **먼저 할 일: 프로토타입 1회 실행 vs 클라우드 납품 오픈** — 둘 다 위험 낮음. 저는 "**프로토타입을 PC에서 감독모드로 딱 한 번 돌려보기**"를 먼저 권합니다(아직 한 번도 안 돌려봤어서 e2e 미확정).

## (e) 위험·주의 (숨기지 않고)

- **PC 꺼지면 다 멈춤** — 스캔·돈 모두. 화면 🟢/🔴 배지로 "왜 안 되는지"는 보이지만 **보인다고 도는 건 아니에요**(결정 2번). PC 상시전원이 이 설계의 물리적 대전제.
- **돈은 아직 코드 0줄** — 프로토타입은 **스캔만** 합니다. 하이브리드 돈 집행은 문서·목업의 계획일 뿐, 라이브엔 한 줄도 없어요.
- **프로토타입 e2e 미검증** — 코드 배선이 맞는 건 확인했지만, 야간엔 PC에 **설치·실행을 하지 않았습니다.** 실제 크롬이 뜨고 스캔이 끝까지 도는지는 대표님이 **한 번 돌려봐야 확정**돼요. (자동시작 `install-task.ps1`은 node가 PATH에 없으면 조용히 안 뜰 수 있어, 먼저 콘솔용 `install/start-agent.bat`로 눈으로 확인 권장.)
- **폴더제안 03의 작은 오류(제가 잡음)** — 03은 "코드에 `Garden` 하드코딩 없음 → 최상위 rename해도 안 깨짐"이라 단정했는데, **`scripts/run-sync.bat`에 절대경로 `…\SIRIAI\Garden`이 박혀 있어 rename 시 이 CLI가 깨집니다**(+`agent/README.md` 설치안내 경로, `src/smm.js`·`scripts/verify-smm.js`의 오류메시지 텍스트 2곳은 표시만 낡음). **라이브 Vercel 배포·`dashboard.bat`·`launch.json`은 진짜 안전**하지만, rename 체크리스트에 **`run-sync.bat` 경로 수정 한 줄을 추가**해야 완전해요.
- **목업의 낙관(제가 잡음)** — 와꾸의 "새 열/새 캠페인 = 코드 수정 0"은 **읽기(헤더기반 인식)엔 사실**(이미 라이브)이지만 **쓰기 경로 field화는 아직 미구현**(아키텍처 3단계 선결). "새 캠페인 = config 하나로 끝"도 실제론 **프로비저닝된 구글시트(URL·토큰)** 가 있어야 해요. 목업은 개념 시연이라 이 부분을 단순화했습니다.
- **무인 자동진행의 미묘함** — "쿠키로 통과되는 것만 자동"이지만 코드는 60초 뒤 진행을 시도하고 막히면 접어요. CAPTCHA를 푸는 건 아니나, 인증 안 된 채 몇 번 시도해 봇 탐지를 살짝 자극할 수 있어요(막히면 '세션 데우기 필요' 배지로 사람 호출).
- **와꾸는 목업** — 버튼은 눌리지만 **가짜 데이터**(실데이터 연결 X), 글꼴 하나(Pretendard)만 외부 CDN이라 인터넷 없으면 대체돼요. 데모 가이드바·설명 노트 등 **데모용 장식은 실제 대시보드로 승격할 땐 걷어내야** 합니다(절제 원칙).
- **야간에 실제 폴더 rename은 안 함** — 하지 말라고 하셨고 안 했어요(라이브가 깨지므로 잘한 것). 03은 계획 문서일 뿐.

## (f) 아침 실행 순서 (위험 낮은 것 → 신중한 것)

1. **프로토타입 눈으로 1회 실행** — `_overnight/agent/install/start-agent.bat` 더블클릭 → 브라우저로 `http://127.0.0.1:3939` → [업로드 스캔](감독) 눌러 **크롬이 진짜 뜨고 스캔이 끝나는지** 확인. (여기서 되면 나머지가 다 이 위에 얹힘)
2. **위험 0짜리 첫 클라우드 이전** — `02` 문서의 **Tier 1: 납품(`/api/deliver`) 한 줄만** 열기. 전부 시트작업이라 안전, 문제 시 그 한 줄만 되돌리면 복구.
3. **폴더 재구성(03)을 함께 실행** — 이름 택1(권장 `campaign-hub`) → 03 체크리스트대로(Vercel Root Directory 수동 변경 + OS 이름변경 후 `git add -A`) **+ `run-sync.bat` 절대경로 수정** 추가. 대표님과 함께, 롤백 가능하게.
4. **돈은 맨 마지막·가장 신중하게** — 결정 1번(A/B) 확정 후 아키텍처 3단계에서. 그전까진 지금처럼 로컬 대시보드로 집행(임시 병존).
