# SIRIAI 브랜드 제안 대시보드 — 제작 PRD

> **한 줄 목적**: **브랜드명 + 홈페이지(또는 인스타) + 인플루언서 리스트** 3개만 주면,
> 그 브랜드 맞춤 **제안 대시보드(HTML) + 회신 메일(TXT)** 가 폴더 하나로 떨어진다.

작성: SIRIAI / 기준 사례: `ponpish/`

| # | 항목 | 예 | 필수 |
|---|---|---|---|
| ① | **브랜드명** | `PONPISH` | ✅ |
| ② | **홈페이지 또는 인스타 URL** | `https://ponpish.co.kr` | ✅ |
| ③ | **인플루언서 리스트** | 구글시트 링크 / CSV | ✅ |
| + | **브랜드 의뢰 원문** (아이보스 등) | "인플루언서·바이럴 찾습니다…" | 메일 만들 때만 |
| + | **인플루언서 사진** | 정사각 1:1 | 있으면 |

> 더 주면 좋은 것(없으면 ②에서 자동 추출): 슬로건, 브랜드 핵심색.

## 2. 출력 — 브랜드 폴더 하나

```
Dashboard/<브랜드>/
  ├ <브랜드>.html              ← 대시보드 (단일 파일, 더블클릭 열람)
  ├ <브랜드>.txt               ← 회신 메일 (Gmail에 그대로 복붙)
  ├ <브랜드>_influencers.csv   ← 정제된 리스트
  └ assets/                    ← 커버 이미지 · 인플루언서 사진(inf/)
```
예) `ponpish/` = `ponpish.html` · `ponpish.txt` · `ponpish_influencers.csv` · `assets/(ponpish_share.png, inf/*.png)`

---

## 3. 진행 범위 변형 — 국내 / 해외 / 둘 다

기본 템플릿엔 **국내(인플루언서 큐레이션)** 와 **해외(시딩 전략)** 가 둘 다 들어있다. 브랜드 상황에 맞춰 고른다:

| 케이스 | 내용 | 슬라이드 |
|---|---|---|
| **국내만** | 국내 인플루언서·커뮤니티 바이럴 중심, 해외 계획 없음 | 해외 슬라이드·진행과정 해외탭 **제거** (← ponpish) |
| **해외만** | 북미/글로벌 시딩(Amazon MCF 등) 중심 | 국내 큐레이션 축소/제거 |
| **둘 다** | 국내 리스트 + 해외 시딩 동시 제안 | 둘 다 유지 (템플릿 기본) |

> **판단**: 의뢰 내용 보고 작업자(=나)가 추천. 예) "20-30 국내 여성 타겟 컬러렌즈" → **국내만** 추천.
> 의뢰에 해외/Amazon/글로벌 언급 있으면 해외 포함.

## 4. 자동 처리 (안 물어봐도 됨)

- **홈페이지/인스타** → 대표색(악센트, 저채도 보정)·커버 이미지·슬로건 추출
  - JS 스토어면 정적 HTML의 `og:image`만 잡힘 → 브랜드 자체 배너/로고를 `assets/`에 받아 사용(클라 자산이라 OK)
  - 표지 figure는 이미지 비율에 맞춰 `aspect-ratio` 조정
- **리스트** → 큐레이션 카드(베스트 4명 featured) + 모달 테이블 + **집계 자동**(합산 팔로워·평균 ER·예상 조회수)
- **단가** → 공개본은 자동 「협의」 마스킹 / `?mode=internal` 에서만 원가
- **사진** → 카드 `img` 연결, 없으면 이니셜 아바타 자동(깨진 이미지 방지)

## 7. 회신 메일 (.txt)

**브랜드 의뢰 원문**을 주면 → SIRIAI 4기둥 메일로 만들어 `<브랜드>.txt` 저장. (Gmail 복붙용 순수 텍스트)

구조:
1. 인사 + 의뢰 확인 + "가입 풀 아닌 직접 발굴" 포지셔닝
2. 가능한 운영 범위 (의뢰 채널 반영)
3. **▸ 제안 대시보드 [링크]** (배포 확정 후 실제 URL)
4. **4기둥** — Insight(데이터·레퍼런스) / Efficiency(35만 vs 15만, 같은 예산 더 많은 콘텐츠) / Empathy(전담 파트너) / Precision(AI·KPI) — 각 한 줄 카피

## 8. 제작 절차 (작업자)

1. `_SIRIAI_TEMPLATE/index.html` → `Dashboard/<브랜드>/<브랜드>.html` 복사
2. config의 **[브랜드 입력]** 블록만 채움: `meta.name/docTitle · brandKit.accent/coverImage · copy.tagline/coverDesc · domestic.comparison/influencers`
3. 리스트 변환기 돌려 `influencers[]` 붙여넣기
4. 진행 범위(3장) 결정 → 불필요 슬라이드/탭 제거 + nav 정리
5. 사진 `assets/inf/` 배치 + 카드 `img` 연결
6. 의뢰 원문 있으면 `<브랜드>.txt` 메일 생성
7. **검증**(콘솔 0 · 오버플로우 · 마스킹) → 로컬 검토 → 확정 시 Vercel 배포 → 메일에 링크 삽입

## 9. "프로그램 만들어야 하나?" — 결론

| 옵션 | 내용 | 평가 |
|---|---|---|
| 현행(반자동) | 템플릿 + 변환기 + 이 PRD로 작업자가 조립. 1건 ~10–15분 | 지금 충분히 굴러감 |
| **권고: Node 생성기** | `build-brand.mjs`: `brand.json`(입력값) + `<brand>.csv`(리스트) → `<brand>.html` + `<brand>.txt` **한 방에 출력** | config 손편집(에러 원인) 제거. 반나절 작업. **물량 늘면 이게 정답** |
| 웹앱/GUI | 폼에 입력하면 생성 | 현재 물량엔 **과함** |

**결론**: 당장은 현행으로 충분. 브랜드 건수가 늘거나 손편집이 귀찮아지면 **`build-brand.mjs` 생성기**를 만든다(웹앱까진 불필요). → 원하면 **"생성기 만들어"** 한마디면 제작.
