# US Seeding — 틱톡 콘텐츠 업로드 확인기

계정 목록을 하나씩 훑어 **최근 10개 게시물**에 지정 키워드(`#ratedgreen` `#rosemary` `@ratedgreen`)를
쓴 콘텐츠가 있는지 확인하고, 찾은 링크를 시트 **O열(Link of content)** 에 기입합니다.

대상 시트: `에녹솔루션_레이티드그린_SIRIAI_Global Seeding_USA_26년`
→ 탭 **USA 70건 배송 및 콘텐츠 업로드** (gid 851028511)

## 처음 한 번만 — 시트 연결 (약 2분)

O열에 자동으로 기입하려면 그 시트에 작은 스크립트를 하나 붙여야 합니다.

1. 시트를 엽니다 → 상단 메뉴 **확장 프로그램 → Apps Script**
2. 편집기에 있는 기본 코드를 지우고, 이 폴더의 **`sheet.gs`** 내용을 통째로 붙여넣습니다
3. 저장(💾) → 함수 목록에서 **`설치확인`** 을 고르고 **실행**
   - 권한 승인 창이 뜹니다 → 내 계정 선택 → "고급" → "…(안전하지 않음)으로 이동" → 허용
   - 아래 실행 로그에 `탭: USA 70건… / 계정 71건 / O열 빈 곳 43건` 처럼 찍히면 정상입니다
4. 오른쪽 위 **배포 → 새 배포** → 톱니바퀴에서 **웹 앱** 선택
   - **다음 사용자로 실행: 나**
   - **액세스 권한이 있는 사용자: 모든 사용자**
   - 배포 → 나오는 **웹 앱 URL** 을 복사
5. 이 폴더의 **`config.json`** 을 열어 `sheet.url` 에 그 URL 을 붙여넣고 저장

> `sheet.gs` 의 `TOKEN` 과 `config.json` 의 `sheet.token` 이 같아야 합니다 (기본값 그대로면 이미 같습니다).
> 이 URL·토큰을 아는 사람만 시트에 접근할 수 있으니 외부에 공유하지 마세요.

## 실행

**`check.bat` 더블클릭** (또는 이 폴더에서 `node run.js`)

1. 크롬 창이 하나 뜹니다. 로봇 인증(퍼즐·슬라이더)이 나오면 **사람이 통과**시켜 주세요
2. 통과했거나 인증이 안 떴으면 → 검은 창에서 **Enter**
3. 계정을 하나씩 확인하며 진행 상황이 찍힙니다

```
  [ 3/43] @aniabella_ugc … 발견 ✓  2026-07-09  #ratedgreen
  [ 4/43] @bea.mer48 … 해당 없음 (영상 10개 확인)
```

4. 끝나면 찾은 링크를 시트 O열에 기입하고 요약을 보여줍니다

한 번 인증을 통과하면 쿠키가 저장돼(`data/tiktok-session.json`) 다음 실행부터는 대부분 인증이 안 뜹니다.

## 중간에 막히면

틱톡이 막으면 **연속 2건 실패 시 스스로 멈추고** 알려줍니다. 조용히 "미업로드"로 넘어가지 않습니다.

```
  ⛔ 중간에 멈췄습니다 — 연속 2건 실패 — 틱톡이 막았을 가능성이 큽니다.
     잠시(10~30분) 뒤 다시 실행하면, 끝난 계정은 건너뛰고 남은 것부터 이어서 합니다.
```

- 그때까지 확인한 결과는 **계정 하나 끝날 때마다** `state.json` 에 저장돼 있습니다
- 찾은 링크는 **멈추는 순간에도 시트에 기입**하고 끝냅니다
- 다시 `check.bat` 을 누르면 남은 계정부터 이어서 합니다
- 계속 막히면 VPN 을 켜거나 `.env` 의 `TIKTOK_PROXY` 를 설정해 보세요 (`.env.example` 참고)

### 차단이 아니라 그 계정 문제일 때

삭제·개명·비공개 계정도 "못 봤음"으로 나옵니다. 차단과 겉으로는 구분되지 않아서:

- 실패한 계정은 다음 실행 때 **큐의 뒤로 미룹니다** — 앞에 두면 매번 같은 자리에서 멈춰
  아직 한 번도 안 본 계정이 계속 밀립니다
- **3번(`maxFails`) 시도해도 안 되면 그만두고** 요약에 따로 모아 보여줍니다.
  시트에는 아무것도 쓰지 않으니 그 계정만 직접 확인하시면 됩니다
- 멈춘 이유도 단정하지 않습니다 — 전에도 실패했던 계정들이면 "삭제·비공개일 수 있다"고 알려줍니다

`check.bat --plan` 을 쓰면 **크롬을 띄우지 않고** 지금 무엇이 남았는지만 볼 수 있습니다.

## 옵션

| 명령 | 하는 일 |
|---|---|
| `check.bat` | 기본 — O열이 빈 계정만 확인하고 시트에 기입 |
| `check.bat --all` | O열에 이미 링크가 있는 계정도 다시 확인 (기존 값은 덮어쓰지 않음) |
| `check.bat --no-push` | 확인만 하고 시트에 기입하지 않음 |
| `check.bat --local` | 시트 대신 `accounts.txt` 의 계정 목록으로 확인 (시트 안 건드림) |
| `check.bat --plan` | 어느 계정을 확인할지만 보여주고 끝 (크롬 안 띄움, 시트 안 건드림) |
| `check.bat --reset` | 지금까지의 확인 기록을 지우고 처음부터 |

`accounts.txt` 는 한 줄에 하나씩 — `@handle`, `handle`, 틱톡 프로필 URL 아무 형태나 됩니다.

## 결과 파일

- **`result.csv`** — 계정 / 발견여부 / 콘텐츠링크 / 업로드일 / 맞은 키워드 / 상태 (엑셀에서 바로 열립니다)
- `state.json` — 체크포인트. 지우면 처음부터 다시 확인합니다

## 설정 (`config.json`)

| 항목 | 뜻 |
|---|---|
| `keywords` | `#태그` 는 해시태그, `@이름` 은 멘션, 그냥 단어는 본문 포함으로 찾습니다. **하나라도 맞으면 발견** |
| `recentN` | 계정당 확인할 최근 게시물 수 (기본 10) |
| `delayMs` | 계정 사이 대기 (기본 8~20초 랜덤 — 고정 간격은 봇처럼 보입니다) |
| `restEvery` / `restMs` | 몇 계정마다 길게 쉴지 (기본 10계정마다 60초) |
| `stopAfterConsecutiveFails` | 연속 몇 건 실패하면 멈출지 (기본 2) |
| `maxFails` | 한 계정을 몇 번까지 다시 시도할지 (기본 3). 넘으면 '확인불가'로 따로 보고 |

## 안전장치

- **작성자 검증** — 프로필 목록에는 추천·리포스트(남의 영상)가 섞여 옵니다. 남의 영상을 **먼저 걸러낸 뒤** 최근 10개를 봅니다 (섞여 온 영상이 자리를 차지해 진짜 영상이 밀려나지 않게)
- **못 본 걸 '없음'이라 하지 않음** — 목록이 전부 남의 영상이면 이 계정 영상을 못 본 것이므로 '해당 없음'으로 확정하지 않고 다시 시도합니다
- **덮어쓰기 금지** — O열에 값이 있으면 그대로 둡니다
- **행 밀림 방지** — 기입 직전에 그 행 B열이 아직 같은 계정인지 다시 확인합니다
- **'못 봤음' ≠ '미업로드'** — 차단·타임아웃은 완료로 찍지 않고, 다음 실행 때 재시도합니다

```
  run.js                 순차 루프 · 체크포인트 · 재개 · 차단 감지
  match.js               키워드 판정 (해시태그 / 멘션 / 본문)
  sheet-client.js        시트 브릿지 호출
  sheet.gs               ← 시트에 1회 붙여넣고 배포
  config.json            키워드 · 간격 · 시트 URL   (git 제외)
  src/                   틱톡 수집 엔진 (Playwright)
  data/                  틱톡 로그인 쿠키          (git 제외)
  state.json result.csv  실행 결과                (git 제외)
```

## Garden 과의 관계

**완전히 독립입니다.** `src/` 의 수집 엔진은 `SIRIAI/Garden` 의 검증된 코드를 **복사**해 온 것이고,
`match.js` 의 해시태그 추출·작성자 검증도 Garden 의 `content-detect.js` 로직을 옮긴 것입니다.
Garden 을 고치거나 지워도 이 도구는 그대로 돌아갑니다 (반대도 마찬가지 — 한쪽 수정이 다른 쪽에 반영되지 않습니다).

처음 설치할 때 Garden 의 틱톡 세션 쿠키를 한 번 복사해 왔기 때문에, 첫 실행부터 로봇 인증이 안 뜰 가능성이 큽니다.
이후로는 이 폴더의 `data/` 에서 각자 갱신됩니다.
