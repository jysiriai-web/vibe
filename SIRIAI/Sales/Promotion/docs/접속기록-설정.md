# 코드 진입 기록 + 열람 횟수(O열) 설정

담당자가 코드를 입력해 페이지에 진입하면 기록이 남습니다. 2단계로 동작합니다.

## 1단계 — 기본값 (설정 불필요, 이미 동작 중)

모든 진입이 Vercel Functions 로그에 구조화 JSON으로 남습니다.

```
[entry] {"ts":"2026-07-20T06:11:59.227Z","code":"TRE2941","brand":"TREEANNSEA 트리앤씨",
         "segment":"skincare","gubun":"스킨케어","ok":true}
```

확인: Vercel 대시보드 → 프로젝트 → **Logs** → `[entry]` 검색.
성공(`ok:true`)뿐 아니라 **오타·미등록 코드(`ok:false`)도 기록**되어 현장에서 어떤 코드가 실패했는지 추적됩니다.

## 2단계 — 마스터시트 O열 열람 횟수 자동 증가 (권장)

Apps Script 웹앱을 붙이면 진입할 때마다
**N열(프로모션 코드)로 행을 찾아 O열(프로모션 코드 열람 횟수)을 +1** 하고, `접속기록` 탭에 로그를 남깁니다.

### 2-1. Apps Script 코드

> ⚠️ **이 문서에서 코드를 복사하지 마세요.** 코드펜스(```)나 제목 기호(#)가 같이 붙어
> `SyntaxError: Invalid or unexpected token` (라인 1) 오류가 납니다.
>
> 리포의 **`docs/apps-script/Code.gs`** 파일을 열어 **전체를 복사**하세요.
> 마크다운 없이 순수 자바스크립트만 들어 있습니다.

마스터시트에서 **확장 프로그램 → Apps Script** → 기존 `Code.gs` 내용을 **전부 지우고**
`docs/apps-script/Code.gs` 내용을 붙여넣은 뒤 저장합니다.

붙여넣은 뒤 **1행이 `/**` 로 시작하는지** 확인하세요.
``` 이나 # 으로 시작하면 잘못 복사된 것입니다.

배포 전 편집기에서 **실행 → `testPing_`** 로 동작을 미리 확인할 수 있습니다
(실제로 시트에 쓰므로, 확인 후 O열 값과 `접속기록` 행은 되돌려 두세요).

### 2-2. 웹앱으로 배포

**배포 → 새 배포 → 유형: 웹 앱**
- 설명: 아무거나
- 실행 계정: **나**
- 액세스 권한: **모든 사용자** ← Vercel 서버가 로그인 없이 호출해야 하므로 필수

배포 후 나오는 `https://script.google.com/macros/s/....../exec` URL을 복사합니다.
(최초 1회 권한 승인 창이 뜹니다 — "고급 → 안전하지 않음으로 이동"을 눌러 승인)

### 2-3. 앱에 URL 연결

```bash
vercel env add ACCESS_LOG_WEBHOOK production   # 위 URL 붙여넣기
vercel --prod --yes                            # 재배포해야 반영됨
```

### 2-4. (권장) 토큰으로 잠그기

웹앱이 "모든 사용자" 공개라 URL이 새면 누구나 카운트를 올릴 수 있습니다. 막으려면:

1. 위 스크립트의 `const SECRET = '';` 에 아무 문자열을 넣고 재배포
   (**배포 → 배포 관리 → 편집(연필) → 버전: 새 버전 → 배포** — URL이 유지됩니다)
2. 앱에 같은 값을 등록:
   ```bash
   vercel env add ACCESS_LOG_TOKEN production
   vercel --prod --yes
   ```

## 동작 확인

코드를 하나 입력해 진입한 뒤 시트를 보면:
- 해당 브랜드 행의 **O열 숫자가 +1**
- **`접속기록` 탭**에 시각·코드·브랜드·성공여부 행이 추가

## 안전장치

- 전송은 **2.5초 타임아웃 + try/catch**로 감싸져 있습니다.
  웹훅이 죽어도 담당자의 코드 입력·페이지 진입은 **절대 막히지 않습니다.**
- `LockService`로 직렬화해 부스에서 동시 진입해도 카운트가 유실되지 않습니다.
- 시트의 개인정보(담당자명·연락처·이메일)는 앱으로 가져오지 않습니다.
  앱이 쓰는 값은 **코드(N) · 브랜드명(E) · 구분(D)** 뿐입니다.

## 코드 레지스트리 갱신

`lib/companies.ts`는 마스터시트에서 생성된 파일입니다(헤더 8행, D/E/N열).
시트에서 코드·브랜드·구분을 수정했다면 **재생성이 필요합니다** — 요청해 주세요.

- 분류 규칙: 구분에 `메이크업` 포함 → 색조(beauty), 그 외(빈칸 포함) → 스킨케어
- 브랜드명이 비었거나 `(unspecified)` 같은 자리표시자면 포괄적인 **"브랜드"** 로 대체됩니다
- **브랜드명 뒤에 을/를·이/가 등 조사를 붙이는 문구는 피하세요.**
  브랜드명의 35%가 영문으로 끝나 한국어 발음을 확정할 수 없습니다
  (KOCOSTAR → "코코스타"인지 "코코스타알"인지 알 수 없음 → 조사 오류).
  현재 카피는 `{브랜드} 맞춤 크리에이터 라인업`처럼 조사 없이 잇습니다.
