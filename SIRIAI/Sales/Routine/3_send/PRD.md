# 3_send PRD — 발송 파이프라인 설계 (compose → 검토 → send → track)

> 범위: `2_compose`가 만든 작성본을 **안전하게 발송**하는 구조. 가장 되돌릴 수 없는 단계라
> ① 법적 안전선(정보통신망법) ② 도달성 안전선(Gmail/스팸) ③ 사람 승인 게이트 세 겹으로 감싼다.
> *(설계 기준: 2026-06 리서치 — 정보통신망법 제50조, Gmail 2026 발신자 가이드라인.)*

---

## 0. 한눈에

```
[1_collector]          [2_compose]            [사람]          [3_send]              [4_reply-tracker]
발송적합도=적합 179  ──▶  훅+템플릿 작성  ──▶  검토·승인  ──▶  승인분만 발송  ──▶  열람/클릭/회신 동기화
   (+메일주의 안전장치)      단계=초안          단계=승인        단계=발송+발송일자        단계=회신…
```

**시트가 상태머신.** 모듈끼리 코드 의존 0 — 오직 시트의 `발송단계` 열로만 연결. 각 단계는 자기 입력 상태만 보고 자기 출력 상태로 바꾼다(멱등).

---

## 1. 상태머신 (진실의 원천 = 시트)

새 열 **`발송단계`** 하나로 전 과정을 추적한다. 값과 전이:

| 발송단계 | 의미 | 누가 세팅 | 다음 |
|---|---|---|---|
| (빈칸) | 아직 작성 안 함 | — | compose가 집음 |
| `초안` | 작성 완료, 검토 대기 | 2_compose | 사람 검토 |
| `보류` | 검토에서 반려(문구 수정 등) | 사람 | compose 재작성 |
| `승인` | 사람이 발송 OK | 사람 | 3_send가 집음 |
| `발송` | 전송 완료 | 3_send | 4_tracker |
| `실패` | 전송 실패(바운스 등) | 3_send | 원인확인·재시도 |
| `회신` | 회신 옴 | 4_tracker | 영업 후속 |
| `제외` | 발송 안 함(수신거부·부적합) | 사람/시스템 | 종료 |

**진입 조건(불변):** `발송적합도 = 적합` 인 행만 `발송단계` 파이프라인에 들어온다. 보류 61행은 `_보류` 시트에 있으니 애초에 대상 아님. → 이중 안전(부적합/민감이 발송에 새는 일 원천 차단).

**멱등 규칙:** 3_send는 `발송단계=승인` 인 행만 집고, 성공 시 `발송`으로 바꾼다. 이미 `발송`이면 건너뜀 → **중복 발송 불가**. (회신/미팅/성사 이력 있는 브랜드 재발송 방지 규칙도 여기서 = `발송단계 in (발송,회신)` 이면 skip.)

## 2. 작성본을 어디에 두나 — `_발송큐` 시트

본문(HTML)은 셀에 넣기엔 길고 더럽다. 그래서 **별도 `_발송큐` 시트**가 발송 작업대 역할:

| 열 | 내용 |
|---|---|
| 발송단계 | 초안/승인/발송/실패/회신 (6월 시트와 동기화) |
| 원래행 | 6월 탭 행번호 (역참조) |
| 브랜드 | 표시용 |
| 이메일 | 수신 주소 |
| 제목 | `[SIRIAI] {brand}에 맞는 인플루언서 제안드립니다` (+[광고] 결정 시 접두) |
| 본문파일 | `2_compose/archive/previews/{brand}.html` 경로 |
| 메일주의 | 1_collector가 박은 안전장치(라엘=생리대 언급금지 등) — **검토자·작성자 필독** |
| 발송일시 | 전송 시각 |
| 결과 | OK / 에러메시지 |

- 본문은 파일(미리보기 HTML)로 두고 경로만 큐에 → 검토자는 HTML 열어 보고, send는 파일 읽어 전송. 셀엔 HTML 안 들어감.
- 큐가 곧 **발송 로그/감사 기록**. 누가 언제 뭘 받았는지 한 줄로 남음.

## 3. 안전선 A — 법적 (정보통신망법 제50조)

콜드메일 = **영리목적 광고성 정보**로 간주될 수 있다. 수신자가 공개한 *사업자* 이메일(info@·biz@·marketing@)이라 개인정보 기반 스팸과는 결이 다르지만(회색지대), **안전하게 가려면 광고성 정보 표기 의무를 지킨다.**

**의무 4종(전송 시):**
1. **[광고] 제목 맨 앞** — 제목 시작 부분에 `(광고)`. 중간·끝·본문은 불인정. *(B2B 제안엔 응답률을 크게 깎음 → §9 결정 항목)*
2. **발신자 명칭·연락처** — 본문 **앞**에 SIRIAI 명칭·담당자·연락처.
3. **무료 수신거부 수단** — 본문 **끝**에 수신거부 방법(원클릭 링크/메일) + "무료" 명시.
4. **야간 금지** — **21:00~익일 08:00 전송 금지**(별도 사전동의 없으면). → send는 **08:00~21:00에만 전송**, 그 외엔 큐에 쌓고 대기.

**설계 반영:**
- send 발송 루프에 **시간대 가드**(현재 KST 08–21 아니면 중단·대기) 하드코딩.
- 템플릿 푸터에 **발신자 정보 블록 + 무료 수신거부 라인** 추가(=`cold_v1.html` 보강 필요, §9).
- 수신거부 처리: 수신거부 요청 시 해당 행 `발송단계=제외` + 별도 `_수신거부` 명단(영구) → 다음달도 재발송 금지.
- `[광고]` 접두는 **켜고/끄는 토글**로 두고 기본값은 사용자 결정 대기(§9). 끄더라도 2·3·4는 지킨다(싸고 리스크 큼).

> ⚖️ 면책: 이건 엔지니어링 설계지 법률자문이 아님. 최종 문구·[광고] 여부는 확정 전 검토 권장.

## 4. 안전선 B — 도달성 (Gmail 2026)

**핵심 현실: 콜드메일 안전 발송량 = 하루 15~25통/계정** (2025말 단속 후). 기존 README의 50~80통은 **계정 화상(스팸 폴더行·정지) 위험**이라 폐기.

| 항목 | 기준(2026) | 설계 반영 |
|---|---|---|
| 신규/미워밍 계정 | 10~30통/일 시작 | 1주차 **12통/일**부터 |
| 워밍업 | 14~21일에 걸쳐 증량 | 12→18→25통 점증 |
| 워밍 후 상한 | 50~100통/일 | 장기 목표, 도메인 성숙 후 |
| 발송 간격 | 사람처럼 | **45~120초 랜덤**(기존 30~90 상향) |
| 스팸률 | <0.1% (레드라인 0.3%) | 회신/스팸신고 모니터 → 초과 시 자동 일시정지 |
| 인증 | SPF/DKIM/DMARC | @gmail.com은 구글 기본 인증뿐 → **커스텀 도메인 권장**(§9) |

**@gmail.com(jysiriai)의 한계:** 개인 Gmail은 DMARC 자체 설정 불가, 콜드 대량발송에 평판 취약. → **권고: 커스텀 도메인(예 `@siriai.kr`)+Workspace+SPF/DKIM/DMARC**. 그게 어려우면 @gmail.com로 **저속(15통/일)·고품질(개인화·짧게)** 만 운용.

**캐던스 계획(179통 기준):**
- 12통/일 시작 → 2~3주 워밍하며 25통/일 → 평균 ~20통/일 → **179통 ≈ 9~12 발송일**.
- 하루치(=오늘 승인분)만 발송, 나머지는 큐 대기. 무인 아님 — **하루 1회 사람 승인**이 곧 속도 제한.

## 5. 3_send 모듈 구조

```
3_send/
├── run.py        진입점: --preview(오늘 승인분 보기) → --send(전송) → --record
├── gmail.py      Gmail API 래퍼: OAuth · send · throttle · 바운스감지
├── compliance.py 정보통신망법 가드: 시간대·[광고]·푸터 검증(전송 전 차단)
├── suppress.py   수신거부/실패 명단 (_수신거부 시트) 로드·체크
└── README.md
```

**인증:** Gmail API OAuth (`jysiriai@gmail.com`, scope `gmail.send`). `_shared`의 서비스계정(시트용)과 **별개** — OAuth 토큰은 `secrets/gmail_token.json`(gitignore). 최초 1회 브라우저 동의.

**의존:** 시트 연동은 `_shared`. 본문은 `2_compose/archive/previews/*.html` 읽음. compose 코드는 import 안 함(시트·파일로만 연결).

## 6. 발송 루프 알고리즘 (run.py --send)

```
전제: --send 는 사람이 그날 큐를 검토하고 승인(발송단계=승인)한 뒤 실행.

1. compliance.guard():
     - 현재 KST 08:00–21:00 인가? 아니면 중단("야간 전송 금지").
     - [광고] 토글 / 푸터(발신자·수신거부) 템플릿에 있는가? 없으면 중단.
2. 오늘 발송 한도 N = warmup_quota(오늘 날짜, 시작일)  # 12→…→25
3. 큐에서 발송단계=승인 행을 위에서 N개 집음.
     - suppress.check(): 수신거부/이전실패 명단이면 제외(발송단계=제외).
     - 중복가드: 6월 발송단계 in (발송,회신) 이면 skip.
4. 각 건:
     a. 본문파일 읽기 → 제목 = compose 규칙(+[광고] 토글)
     b. gmail.send(to, subject, html)
     c. 성공 → 발송단계=발송 + 발송일시 + 6월 시트 발송일자 기록
        실패 → 발송단계=실패 + 결과(에러). 다음 건 진행(멈추지 않음).
     d. sleep(random 45~120초)   # 평판 보호
     e. 누적 스팸/바운스율 > 임계 → 즉시 일시정지 + 알림
5. 요약 출력: 발송 n · 실패 m · 남은 큐 k · 다음 발송 가능 시각.
```

**왜 무인 아님:** 4(d) throttle 때문에 25통이면 ~30~50분 걸림. 사람은 `--send` 한 번 누르고 두면 됨. 승인 게이트가 핵심 — **자동 승인 절대 없음.**

## 8. 결정 필요 (§9)

1. **[광고] 제목 접두 켤까?**
   - 켜면: 법적 안전 ↑, 응답률 ↓(스팸 느낌). 끄면: 응답률 ↑, 회색지대 리스크.
   - 권고: **발신자 정보+무료 수신거부+야간금지는 무조건 적용**, [광고]만 결정. (B2B 제안 성격이면 끄는 곳 많으나 본인 판단.)
2. **발신 도메인:** @gmail.com(jysiriai)로 저속 시작 vs **커스텀 도메인+Workspace**(도달성·확장성 ↑). 진지하게 돌릴 거면 후자 강력 권고.
3. **Gmail OAuth 셋업:** `gmail.send` 동의 1회 + `secrets/gmail_token.json`. (내가 가이드 만들어 줄 수 있음.)
4. **발송량/워밍업:** 시작 12통/일 → 25통/일 안 vs 다른 속도. 179통 ≈ 9~12일.
5. **수신거부 수단:** 원클릭 링크(랜딩 필요) vs 회신형("수신거부 회신주세요"). 후자가 셋업 0.
6. **발신자 푸터 문구:** SIRIAI 명칭·담당자명·연락처·주소(법적 표기용) 확정.

## 9. 설계 원칙 요약
- **시트=상태머신, 모듈 코드 의존 0** (이전 모듈 패턴 계승).
- **3겹 안전선:** 적합도 필터(이미 됨) → 법적 가드 → 사람 승인.
- **되돌릴 수 없으니 보수적으로:** 저속·고품질·중복불가·야간금지·실패격리.
- **메일주의(안전장치) 전 구간 동행:** 큐에 박혀서 검토자·작성자가 항상 봄 (라엘 생리대 사고 방지).
