# 9_report — 운영 현황 대시보드 (⬜ 설계)

## 1. 목적

6월(및 이후 월별) 탭에 쌓인 추적 열을 읽어 **캠페인 퍼널 전체를 숫자로 보여주는 HTML 대시보드**를 생성한다. 발송 N건이 열람 → 클릭 → 회신 → 리드 → 미팅 → 계약 → 성사로 얼마나 흘렀는지, 어느 구분(카테고리)이 잘 됐는지, 월별로 추세가 어떻게 변하는지를 한 파일에 정리한다. 운영자가 매일 아침 `report/index.html`을 열어 전체 상황을 파악하는 **최종 현황판**이다. 시트를 직접 수정하지 않으므로 되돌릴 필요가 없고, 산출물은 로컬 HTML 파일뿐이다.

## 2. 데이터 계약

### 2-1. 입력 — 시트에서 읽는 것

| 시트/탭 | 열 | 의미 | 비고 |
|---|---|---|---|
| 월별 탭(6월 등) | B 구분 | 카테고리(뷰티·리빙·F&B …) | 집계 분해 축 |
| 월별 탭 | C 브랜드명 | 행 식별자 | |
| 월별 탭 | D 연락처(이메일) | 발송 대상 확인용 | 빈 행 = 발송 전 |
| `_발송큐` 탭 | 발송단계 | 초안·승인·발송·회신·관심·리드·미팅·계약·성사·거절·무응답·종료·제외 | 상태머신의 핵심 |
| `_발송큐` 탭 또는 월별 탭 | 발송(Y/N 또는 날짜) | 발송 완료 여부 | |
| 월별 탭 | 열람(Y 또는 날짜) | 오픈 여부 | 참고치 — 부정확 |
| 월별 탭 | 클릭(Y 또는 날짜) | 링크 클릭 여부 | 참고치 |
| 월별 탭 | 회신(Y/N) | 회신 유무 | |
| 월별 탭 | 미팅(Y/N) | 미팅 성사 여부 | |
| 월별 탭 | 발송일자 | 발송 날짜(YYYY-MM-DD) | 시계열 분해 |
| 월별 탭 | 회신일자 | 회신 날짜 | 응답 속도 계산 |
| 월별 탭 | 성사여부(Y/N) | 계약 성사 | 최종 KPI |
| 월별 탭 | 메일주의 | 민감 제품군 경고 문자열 | 집계에서 별도 표시 |

> 탭 이름 목록과 열 번호는 `../_shared/config.py`에서 관리. `9_report/run.py`는 거기서만 읽는다.

### 2-2. 출력 — 이 모듈이 쓰는/만드는 것

| 출력 | 경로 | 형태 | 비고 |
|---|---|---|---|
| HTML 대시보드 | `9_report/report/index.html` | 단일 HTML(인라인 CSS·JS) | 브라우저에서 바로 열림 |
| 집계 스냅샷 | `9_report/report/snapshots/YYYYMMDD_HHMM.json` | JSON | 시계열 비교·백업용 |
| 실행 로그 | `9_report/report/run.log` | 텍스트 | 오류 추적 |

**시트 쓰기 없음.** 이 모듈은 시트를 읽기만 한다. 어떤 열도 갱신하지 않는다.

## 3. 메커니즘

### 3-1. 전체 흐름

```
[run.py --build]
  ↓
1. _shared/sheets.py 로 대상 탭 목록 조회 (월별 패턴 탭: 6월·7월 …)
  ↓
2. 각 탭 전체 행 읽기 → Row dict 리스트로 변환
  ↓
3. aggregator.py: 퍼널 집계 + 구분별 분해 + 월별 시계열 계산
  ↓
4. renderer.py: 집계 결과 → HTML 주입 → index.html 저장
     └→ snapshots/YYYYMMDD_HHMM.json 저장
  ↓
5. 콘솔에 핵심 수치 요약 출력 (발송·회신율·성사 수)
```

### 3-2. 집계 항목 상세

**퍼널 KPI (전체 합산)**

| 지표 | 계산 방법 |
|---|---|
| 발송 N | 발송단계 ≠ 초안·승인·제외 인 행 수 (또는 발송일자 있는 행) |
| 열람율 | 열람=Y 행 수 / 발송 N × 100 (참고치 표기) |
| 클릭율 | 클릭=Y 행 수 / 발송 N × 100 (참고치 표기) |
| 회신율 | 회신=Y 행 수 / 발송 N × 100 |
| 리드 N | 발송단계 ∈ {관심·리드·미팅·계약·성사} 행 수 |
| 미팅 N | 미팅=Y 또는 발송단계 ∈ {미팅·계약·성사} 행 수 |
| 성사 N | 성사여부=Y 또는 발송단계=성사 행 수 |
| 수신거부 N | 발송단계=제외 행 수 |

**구분별 분해**
- B열 구분 기준으로 위 KPI를 그룹핑. 뷰티/리빙/F&B 등 각 버킷에 대해 발송·회신·성사 수 표시.

**월별 시계열**
- 탭 이름이 "N월" 패턴인 탭을 발송일자 기준 월로 정렬, 회신율·성사율 추이 표시.

**메일주의 현황**
- `메일주의` 열에 값이 있는 행 수와 비율을 별도 섹션에 표기(민감 제품군 규모 인지용).

### 3-3. HTML 생성 방식

- **단일 파일 원칙:** `index.html` 안에 CSS와 집계 데이터를 인라인 JSON으로 내장. 외부 서버 불필요, 브라우저에서 파일을 그냥 열면 된다.
- **Chart.js CDN:** 퍼널 막대그래프와 월별 라인차트는 Chart.js(CDN, fallback graceful)를 사용. CDN이 없으면 숫자 테이블만 표시.
- **SIRIAI 브랜드 토큰:** Paper `#F3EEE2` 배경 / Ink `#211A33` 텍스트 / 영문 Arimo / 국문 Pretendard / 레이블·수치 JetBrains Mono. CSS 변수로 정의.
- **LLM 사용 없음.** 집계·렌더링은 순수 Python + Jinja2(또는 f-string 템플릿). 외부 API 호출 없어서 오프라인에서도 실행 가능하고 비용도 없다.

### 3-4. 실행 모드

```powershell
# 기본: 전체 월 탭 집계 → index.html 갱신
python 9_report/run.py --build

# 특정 탭만
python 9_report/run.py --build --tab 6월

# 콘솔 요약만(파일 저장 안 함)
python 9_report/run.py --summary
```

`--build`는 언제 몇 번 실행해도 안전하다(읽기 전용 + 덮어쓰기 무해).

## 4. 상태 전이

**이 모듈은 시트의 어떤 열도 바꾸지 않는다.** 발송단계·영업단계는 읽기만 한다.

따라서 이 모듈이 트리거하는 상태 전이는 없다. 파이프라인에서 이 모듈의 역할은 모든 이전 모듈(1~8)이 시트에 기록한 상태를 **집계·시각화**하는 것이다.

| 읽는 상태(발송단계) | 집계 버킷 |
|---|---|
| 초안·승인 | 발송 전 (미발송 재고) |
| 발송 | 발송 완료 |
| 열람·클릭 | 반응 있음(참고치) |
| 회신 | 회신 도착 |
| 관심·리드 | 영업 진행 중 |
| 미팅 | 미팅 단계 |
| 계약·성사 | 전환 완료 |
| 거절·무응답·종료 | 소멸 |
| 제외 | 수신거부·영구 제외 |

## 5. 안전·주의

### 되돌리기
- 이 모듈은 시트에 쓰지 않으므로 되돌릴 내용이 없다.
- HTML 파일 덮어쓰기 전에 `snapshots/` 폴더에 날짜·시간 이름 JSON 스냅샷을 저장하므로, 이전 수치가 필요하면 JSON에서 복원 가능하다.

### 이중 처리 방지
- 집계는 멱등: 같은 입력 → 같은 출력. 몇 번 돌려도 HTML은 같은 수치로 갱신된다.
- `snapshots/`에 타임스탬프별로 쌓이므로 "같은 날 두 번 실행"도 이전 스냅샷을 덮지 않는다.

### 사람 승인 게이트
- 이 모듈 단독으로는 불필요하다. 시트 쓰기가 없고, HTML 파일 생성은 되돌릴 수 있다.
- 야간 cron으로 자동 실행해도 무방하다.

### 메일주의 표시
- `메일주의` 열에 값이 있는 브랜드는 집계 테이블에서 ⚠ 아이콘과 함께 표시한다.
- 대시보드 상단에 "메일주의 브랜드 N건 포함" 배너를 두어 운영자가 맥락을 잃지 않게 한다.
- 해당 브랜드의 발송·회신 수치도 포함해서 집계하되, 주석으로 민감 여부를 병기한다.

### 수신거부 가시화
- `발송단계=제외` 행은 퍼널에서 별도 카운터로 표기(수신거부 누적 N건). 운영자가 수신거부 규모를 항상 인지하도록 한다.

### 열람·클릭 수치 신뢰도 표기
- 열람/클릭율 옆에 "(참고치 — 오픈 추적 부정확)" 레이블을 명시해서 과대해석을 방지한다.

## 6. 구현 메모

### 6-1. 예상 파일 구조

```
9_report/
├── run.py              진입점 (--build / --summary / --tab N월)
├── aggregator.py       시트 행 리스트 → 집계 dict 계산
├── renderer.py         집계 dict → index.html 생성 (Jinja2 또는 f-string)
├── templates/
│   └── dashboard.html  HTML 골격 (Chart.js + SIRIAI 토큰 내장)
├── report/
│   ├── index.html      생성 산출물 (git 제외 권장)
│   └── snapshots/      YYYYMMDD_HHMM.json 누적
└── README.md
```

`run.py` 역할:
1. `_shared/sheets.py`로 시트 열기
2. 대상 탭 목록 결정(전체 월 탭 또는 `--tab` 지정)
3. 각 탭 전 행 읽기 → `aggregator.aggregate(rows, tab_name)` 호출
4. 월별 결과 합산 → `renderer.render(data)` → `report/index.html` 저장
5. 콘솔에 요약 출력

### 6-2. 의존

| 의존 | 용도 | 기존 여부 |
|---|---|---|
| `../_shared/sheets.py` | 시트 접근·인증 | 있음 |
| `../_shared/config.py` | SHEET_ID·탭이름·열 번호 | 있음 |
| `jinja2` | HTML 템플릿 렌더링 | requirements.txt 추가 필요 |
| `Chart.js` | 그래프 (CDN) | 설치 불필요 |
| `Pretendard` | 폰트 (CDN 또는 로컬) | 설치 불필요 |

Gmail OAuth 불필요. LLM API 불필요. 추가 서비스 인증 없음.

### 6-3. `_shared/config.py` 추가 필요 항목

현재 `config.py`에는 B·C·D 열(구분·브랜드명·이메일)만 매핑되어 있다. 아래 열을 추가해야 이 모듈이 동작한다.

| 키 (예시) | 열 | 현재 상태 |
|---|---|---|
| `col_send_stage` | 발송단계 | 미정 — 실측 필요 |
| `col_open` | 열람 | 미정 |
| `col_click` | 클릭 | 미정 |
| `col_reply` | 회신 | 미정 |
| `col_meeting` | 미팅 | 미정 |
| `col_send_date` | 발송일자 | 미정 |
| `col_reply_date` | 회신일자 | 미정 |
| `col_deal` | 성사여부 | 미정 |
| `col_caution` | 메일주의 | 미정 |
| `MONTHLY_TAB_PATTERN` | 탭 이름 패턴(예: `r'\d+월'`) | 미정 |

**이 열 번호 확정이 구현 착수의 선결 조건이다.** 시트 구조가 변경되면 `config.py`만 수정하고 이 모듈은 건드리지 않는다.

### 6-4. 미정·결정 필요 항목

1. **`_발송큐` vs 월별 탭 중 어느 쪽에 발송단계가 있는가?** 현재 월별 탭에도 추적 열이 있고 `_발송큐`에도 상태가 있어 출처가 두 곳이다. 어느 쪽을 집계 기준으로 삼을지 확정 필요.
2. **열람·클릭 데이터 경로.** Mailsuite CSV 파일인지, 직접 기록한 열인지에 따라 읽는 방법이 다르다.
3. **cron 주기.** 매일 자동 실행(야간)이 적합하나, `/schedule`로 등록할 시점과 주기(예: 매일 07:00)를 결정 필요.
4. **report/ 폴더의 git 관리.** `index.html`과 `snapshots/*.json`은 산출물이므로 `.gitignore`에 넣는 것이 원칙이나, 히스토리 보존 목적이면 snapshots는 포함할 수도 있다. 결정 필요.
5. **Vercel 배포 여부.** 로컬 HTML로만 운영할지, Vercel에 올려 URL로 공유할지. 현재 설계는 로컬 우선이며, 배포는 최종 확정 시에만 진행(배포 워크플로우 원칙 준용).
