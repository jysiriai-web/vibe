### ① 주문 요청이 응답을 못 받았을 때 (돈)

**상황.** SMM 패널에 주문을 넣었는데 응답을 못 받는 경우가 세 가지예요.

| 경우 | 돈이 나갔나 |
|---|---|
| 패널이 "거절"이라고 명시 | **안 나갔음 (확실)** |
| 네트워크가 끊김 | **모름** |
| 502·차단 페이지(JSON 아님) | **모름** |

지금 코드는 세 경우를 **전부 "돈 안 나갔다"로 단정**하고 다음 계정으로 넘어가요.
기록이 안 남으니 다음 집행에서 **같은 계정을 또 사서 팔로워가 두 배로 들어옵니다.**

**선택지**

| | 하는 일 | 좋은 점 | 나쁜 점 |
|---|---|---|---|
| **A** | 그 자리에서 배치 중단. 이미 나간 주문 목록만 보여주고 멈춤 | 구현이 가장 작고 확실 | 기록이 없어서, 패널 확인을 잊고 재집행하면 여전히 2회 과금 |
| **B** (추천) | 「패널 확인 필요」 주문으로 기록을 남기고 중단 → 재주문이 **구조적으로** 막힘 | 사람 기억에 안 기댐 | 포기 버튼·화면 표시까지 같이 만들어야 함 (작업량 3~4배) |
| **C** | 그 계정만 잠그고 나머지는 계속 집행 | 밤 배치가 한 계정 때문에 안 섬 | "돈 나갔을 수 있다"는 신호가 완료 알림에 묻힘 |

**추천은 B.** 이 시스템의 다른 돈 경로가 전부 "기록이 없으면 멈춘다"로 통일돼 있어서요.
급하면 A 를 먼저 넣고 B 로 올려도 호환됩니다.

### ② 「모집 가져오기 · 인원 추가 · 새로고침」 버튼 자리

어제 "필터 오른쪽 끝으로 옮기면 좋겠다"고 하셨는데,
그 사이 **필터가 하위탭으로 올라가면서 그 줄 자체가 없어졌어요.**
지금은 하위탭 아래 한 줄에 있습니다. 어디로 둘까요?

- **가** 하위탭(전체·틱톡·인스타…) 줄의 오른쪽 끝 — 원래 의도에 가장 가까움
- **나** 지금 자리 유지
- **다** 상단바(지금 비어 있음)로

- **가** 만든다 — 대시보드에서 사람 추가가 완결됨
- **나** 안 만든다 — 사람 추가는 마스터시트에서 직접 (실제로 그렇게 쓰고 계시면 이쪽)

## 2. 밤새 고친 것

야간 검수에서 **31건**이 확인됐고, 그중 **결정이 필요 없는 것 전부**를 고쳤어요.
아래는 "이게 왜 문제였나" 위주로 정리한 거예요.

### 화면에서 바로 보이는 것

| 무엇 | 어땠나 |
|---|---|
| **정산 탭 전체** | 정산방식·우수 선정·개별단가·입금·비고 **전부 화면에서만** 바뀌고 20초 뒤 원래대로 돌아갔어요. 이제 시트에 쓰고 다시 읽습니다 |
| **미러링** | 화면에서 「오리지널」을 고르면 시트엔 **「별개」**가 갔어요 — 드롭다운이 튕겨냅니다 |
| **납품 탭** | 열자마자 **빈 표**였어요(통합 상태에서). 사람×플랫폼 표로 새로 만들었습니다 |
| **일정 미준수** | 확정일을 **무시하고** 원래 희망일로만 지연을 셌어요. 날짜를 뒤로 합의한 사람이 지연으로 잡혔습니다 |
| **가드닝 「채워지는 중」** | 진행중 주문이 **늘 0**이라 이미 채워지는 계정이 다시 대상으로 떴어요 |
| **죽은 버튼** | 조회수 스캔·납품 기입이 **존재하지 않는 함수**를 부르고 있었어요(눌러도 아무 일 없음). 실제 API 로 이었습니다 |
| **인원 추가** | 브라우저 안에서만 늘고 사라지면서 "시트에 한 줄 늘리는 것과 같아요"라고 했어요 → 정직하게 바꿨습니다 (→ 물어볼 것 ③) |

### 안 보이지만 더 위험했던 것

- **시트 헤더행을 못 찾으면 「다른 캠페인 좌표」로 추측해서 읽고 썼어요.** 막는 장치가 있었지만 검사 대상이 어긋나 한 번도 안 걸렸습니다. 이제 못 찾으면 읽기·쓰기 둘 다 거부하고 이유를 말해요.
- **「인스타 콘텐츠②(미러/추가)」 열을 못 알아봤어요.** 괄호 때문에요. 그 한 칸 때문에 **인스타 콘텐츠 스캔 배치 전체가 실패**로 보고됐습니다.
- **`#LUN8✨` 처럼 이모지가 붙은 해시태그를 못 읽었어요.** 정상 게시물이 「미업로드·해시태그 미준수」가 되고, 그대로 **잘못된 수정요청이 크리에이터에게 나갈** 뻔했습니다.
- **비공개 계정 하나가 「차단당했다」로 오인**돼 스캔 전체가 40초/계정짜리 느린 경로로 떨어졌어요.
- **게시물을 0개 봐도 「미업로드」로 확정**했어요. 로그인 창이 뜬 건지 진짜 안 올린 건지 구분이 안 되는데요.
- **시트 쓰기가 실패해도 「업로드 완료」로 확정**해서, 그 계정이 **영영 재스캔에서 빠졌어요.** 복구 경로도 없었고요.
- **스캔이 사람이 고친 검수를 그대로 덮어썼어요** (인스타는 잠금을 아예 안 봤고, 틱톡은 열쇠 이름이 어긋나 있었어요).
- **주문(돈) 기록만 유일하게 「동시 수정 방지」 밖에 있었어요.** 20초 화면 새로고침이 방금 종료·포기한 주문을 낡은 값으로 되살렸습니다.
- **CLI 집행이 시트가 아니라 로컬 파일을 읽었어요** → 진행중 주문을 못 봐서 **같은 계정을 또 살** 수 있었습니다.
- **작업 콘솔이 공개 URL 에서 그대로 열렸어요** (`/worker.html/` 처럼 슬래시 하나만 붙이면). 이제 배포본에 아예 없습니다.
- **스캔 「완료 N개」가 시도한 수**였어요 — 전건 실패해도 N개로 보였습니다.

### 확인한 방법

- 대시보드 **7개 탭 × 하위탭 전부** 실제로 열어 오류 0건 확인
- 정산 5개 칸이 시트로 보내는 값 **직접 가로채 확인** (`pay/best/override/paid/settleMemo`)
- 한글 값 **시트 왕복 실측** — 썼다가 읽고 원상복구까지
- Apps Script 브릿지 **@17 로 재배포**

## 3. 고친 걸 다시 검증했어요 (적대적 재검토)

고친 코드가 **새 문제를 만들지 않았나**를, 서로 다른 각도의 검토자들로 다시 뒤졌어요.
36개 지적 중 **18개가 반증을 견뎠고**, 그중 지금 실제로 문제가 되는 **높은 것 3개는 바로 고쳤습니다.**

| 무엇 | 어땠나 | 처리 |
|---|---|---|
| **인스타 링크 저장** | 링크를 시트에 쓰기 시작하면서 「@핸들」을 그대로 넣었는데, 브릿지는 URL만 읽어요 → **그 행이 통째로 사라졌어요** (인스타 전용 2명 소멸) | ✅ URL로 정규화 후 저장 + 서버 검증 |
| **검수 추정값 누출** | 스캔이 추정한 「미준수」가 사람이 판정한 것처럼 검수칸에 떠서, 잘못된 수정요청 근거가 됐어요 | ✅ 추정값은 검수칸에 안 씀 |
| **선택 스캔** | 시트 쓰기 실패·못 본 계정을 다 삼키고 「완료」라고 했어요 | ✅ 실패를 먼저 알림 |

나머지 15개는 **낮은 심각도**거나 원래 있던 것이라 보류했어요 (납품 기입의 인스타 누락은 LUN8이 납품시트 설정이 없어 버튼이 이미 정직하게 실패해요 — 다음 캠페인 때 처리). 필요하면 목록 드릴게요.
