# SIRIAI 사업소개 Deck — 점검 의뢰서 (이 문서 하나로 진행)

> **클로드 디자인에게 —**
> 이건 점검 의뢰서야. 이 문서를 **끝까지 읽고**, 네가 지금 작업 중인 deck을 아래
> **‘A. 맥락(목적)’을 기준으로 ‘B. 점검 지시’대로 전수 점검**해서 **리포트만** 내줘.
> - 추가 질문 없이 이 문서 하나로 바로 진행해.
> - 방금 토큰이 리셋돼 예산 넉넉하니, 시간·길이 아끼지 말고 **최대한 깊고 발산적으로, 끝까지.**
> - ⛔ 원본 deck은 절대 수정하지 마(예외는 B-2 참고). 수정은 사람이 아침에 직접 판단한다.

# A. 맥락 — 이 deck의 목적 (판단 기준)

세부 텍스트·레이아웃은 기획·구현 중 계속 바뀌었으니, **세부 구현을 정답으로 보지 말고
아래 거시적 목적·원칙에 비춰** 판단해. (이건 평가 기준이지, 이대로 새로 만들라는 게 아님.)

## 1. 무엇인가 (한 줄)
아웃바운드 세일즈 메일에 링크로 붙는 **경험형 챗봇 상품소개 랜딩**.
홈페이지가 아니라, 메일 받은 사람이 클릭해 들어와 SIRIAI가 뭐 하는 곳인지 "경험"하는 한 장짜리.

## 2. 누가 보나
- 뷰티·패션·라이프스타일 브랜드의 **담당자/대표(의사결정자)**.
- 핵심: **다 관심 있어서 온 게 아님.** 그냥 눌러본 사람, 관심 있어도 행동 안 할 사람 포함.
  → 첫인상이 일을 해야 함.

## 3. 사용자가 해야 할 행동 (목표)
- 처음 본 2초 안에: ① 이거 인터랙티브하다 ② 누르면 안에 내용이 더 있다 ③ 4개가 서로 다른 영역이다
  — 머리로 추론이 아니라 **직감으로** 알게.
- 관심 영역 클릭 → Q&A 챗봇으로 궁금증 해소 → **문의(CTA)** 로 전환.

## 4. 구조
히어로 → 4개 영역 카드(미리 고르는 브릿지) → 영역별 Q&A 챗봇 → 문의.
영역: 국내 인플루언서 / 글로벌 인플루언서 / 셀러브리티 & 아티스트 / 브랜딩 비즈니스.

## 5. 톤 & 무드 (브랜드 인격)
- 감성 + 테크니컬 **동시에**. 챗봇 경험 자체가 '테크니컬'의 증거.
- **진짜 심플**: 정보·텍스트·요소를 늘리는 게 미덕이 아님. 빼기가 디폴트. (과밀 = 가장 흔한 실수)
- 느린 무드, 넉넉한 여백, 차분함. "아무렇지 않게 사업 잘하고 있다"는 여유.
- "우리 지린다" 자랑 X → "당신 페인포인트를 이미 이해하고 있다"는 신뢰.
- 결: 에디토리얼·갤러리 같은 정제됨 (홈페이지 톤 준용).

## 6. 디자인 토큰 (준수)
- 색: Paper(크림) 배경 · Ink(딥) 텍스트 · 따뜻한 워시(피치·라일락) 은은하게.
  강조는 그라데이션(coral→violet→blue) **절제** 사용.
- 폰트: 국문 Pretendard / 영문 Helvetica·Arimo / 라벨·메타 JetBrains Mono(대문자·자간 넓게).
  ⛔ Schibsted Grotesk · Inter · Roboto 금지.
- 형태: 두꺼운 컬러 박스·진한 드롭섀도 **금지**. 에디토리얼하게. radius 절제, 여백 넉넉, 한 화면 한 메시지.
- 국문 제목 word-break: keep-all, 큰 제목일수록 자간 좁게.

## 7. 표시 규칙 (게이트 — 어기면 실격)
- 단가·금액 숫자 노출 금지.
- 미검증 수치(과장 통계·성과수치) 금지.
- 해외 = "직접 운영" 표현 금지 → "검증된 파트너망" 톤.
- 셀럽 = 실명·얼굴(초상권) 노출 금지 → 매거진 로고 등으로 신뢰 대체.
- 브랜드 실명·로고는 동의된 것만.

## 8. 성공 기준 (이걸로 판단)
1. 첫인상에서 "인터랙티브 + 더 있다 + 내 영역"이 직감되는가?
2. 심플·여백·느린 무드가 유지되는가 (과밀하지 않은가)?
3. 4영역이 각자 정체성을 갖되 하나의 브랜드로 일관되는가?
4. 톤이 "여유 + 페인포인트 이해"인가 (자랑·벤더 말투 아님)?
5. 브랜드 토큰·게이트를 안 어기는가?
6. 모바일에서도 위 경험이 살아있는가?

# B. 점검 지시

‘A. 맥락’을 기준으로 deck을 **아주 사소한 것 하나까지 전수 점검**해줘.

## B-1. 절대 규칙
1. **원본 deck을 직접 수정하지 마.** 너는 ‘점검·리포트’만. 수정은 사람이 아침에 직접 판단.
2. 예외 — 명백한 버그/오류(깨진 이미지, 잘린 텍스트, 작동 안 하는 버튼, 명백한 오타 등)로
   고쳐도 100% 안전한 것만: **원본은 그대로 두고, 새 캔버스(페이지) 복제본을 만들어 거기서만** 고쳐.
   무엇을 왜 고쳤는지 리포트에 적어. 애매하면 고치지 말고 리포트에만 남겨.
3. 확신 없는 건 "확인 필요"로 표시. 사실관계·게이트 위반은 '의심'만 플래그(네가 단정하지 마).

## B-2. 점검 차원 — 데스크톱 + 모바일 둘 다
- 타이포: 폰트 종류(토큰 준수/금지폰트 여부), 자간(letter-spacing), 행간, 크기 위계, 굵기, 국문 keep-all.
- 색: 토큰 색 준수, 대비·가독성, 워시·그라데이션 절제, 영역 간 일관.
- 이미지: 화질, 비율, 잘림, 톤 일관, 깨진 이미지, 얼굴/초상권 게이트 위반 여부.
- 레이아웃·여백: 정렬, 여백 일관, 그리드, 데드스페이스, 이미지:텍스트 균형, '한 화면 한 메시지'.
- 시각 위계: 처음 눈에 뭐가 먼저 오나 → A-3 첫인상 의도(인터랙티브·더있음·내영역)에 부합하나.
- UI/UX·인터랙션: 클릭 가능함이 직감되나, hover/모션이 적절·일관·안 끊기나, 로딩·라우팅·CTA 명확한가.
- 모바일/반응형: 좁은 화면 레이아웃·터치 타깃·가독성, 데스크톱 모션의 모바일 대체가 자연스러운가.
  (실기기 테스트는 못 하더라도, 코드·구조 기준으로 추론해서 **모바일 수정 포인트를 반드시 내라.**)
- 카피·톤: A-5 톤 일관(자랑·벤더 말투 없는지), A-7 게이트 위반 의심 카피.
- 일관성: 4카드/4영역·컴포넌트·반복요소가 통일됐나.
- 마이크로: 오타, 1px 정렬, 아이콘·모서리·호버상태 등 진짜 사소한 것까지.

## B-3. 출력 형식 (리포트)
- 맨 위: 한 줄 총평 + A-8 "성공 기준 6개" 각각 통과/주의/미달 한 줄 평가.
- 그 다음: 발견 항목 리스트. 각 항목은 →
  · 위치(어느 화면/영역) · 차원 · 문제(무엇이 어떻게) · 어긋난 기준(A-§몇/토큰) · 제안 · 심각도(상/중/하)
- 별도 섹션: ① 새 캔버스에서 고친 명백한 버그(있으면) ② 확인 필요(네가 판단 못 한 것).
- 토큰·길이 아끼지 마. 리셋 직후라 예산 넉넉하니 '하'·마이크로까지 **빠짐없이, 발산적으로 깊게.**
  (정렬만 심각도 '상' 먼저 — 가독성용.)
- 리포트 전체를 **한 메시지에 정리**해줘(사람이 아침에 한 번에 읽게).
